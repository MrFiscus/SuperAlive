# SuperAlive

Keeps free-tier Supabase projects from being **paused after 7 days of inactivity**.

A scheduled GitHub Action pings each of your databases every 3 days. No server, no
Vercel app. One workflow handles any number of projects.

## Setup

Takes about five minutes.

### 1. Fork this repo

Click **Fork** at the top right. This step matters: the workflow runs on your GitHub
account's Actions minutes and reads a secret stored on your own repository, so it cannot
run from someone else's copy.

### 2. Enable Actions on your fork

Open the **Actions** tab and click the button confirming you want workflows to run.
GitHub disables workflows in forks by default, so nothing happens until you do this.

### 3. Create the table in each Supabase project

In every project you want kept alive, open the **SQL Editor** and run
[`sql/keep-alive.sql`](sql/keep-alive.sql):

```sql
create table if not exists "keep-alive" (
  id bigint generated by default as identity primary key,
  name text default '',
  random uuid default gen_random_uuid()
);
insert into "keep-alive" (name) values ('keep-alive');
```

### 4. Build your config

Open [`setup/index.html`](setup/index.html) in a browser. Double-clicking the file is
enough, there is nothing to install or serve.

For each project, copy the **Project URL** and an **API key** from
**Settings → API** in the Supabase dashboard, and press **Test connection** to confirm
the table is reachable. The page then generates the config for you. Everything runs
client-side, so your keys are never uploaded anywhere.

Prefer to write it by hand? It is a plain JSON array, one object per project
(see [`targets.example.json`](targets.example.json)):

```json
[
  { "name": "project-one", "url": "https://aaaa.supabase.co", "key": "eyJ..." },
  { "name": "project-two", "url": "https://bbbb.supabase.co", "key": "eyJ..." }
]
```

### 5. Save it as a repository secret

The secret must be named exactly `SUPABASE_KEEPALIVE_TARGETS`.

Via the web UI: **Settings → Secrets and variables → Actions → New repository secret**,
then paste the config as the value.

Or save the config locally as `targets.json` (already gitignored) and run:

```bash
gh secret set SUPABASE_KEEPALIVE_TARGETS < targets.json
```

### 6. Verify

Go to **Actions → SuperAlive → Run workflow**. The log should print a `✓` for every
project. After that it is hands-off, running every 3 days on its own.

To add or remove a project later, run the SQL in the new project and update that one
secret. No code changes.

## How it works

Each project gets a tiny `keep-alive` table. Every 3 days
[`keep-alive.yml`](.github/workflows/keep-alive.yml) runs
[`keep-alive.sh`](scripts/keep-alive.sh), which does one PostgREST read per project using
a random filter value so nothing can answer it from cache. That read counts as activity.

## Good to know

- **GitHub disables scheduled workflows after 60 days with no commits.** Any push resets it.
- Cron timing is best-effort. The 3-day interval leaves margin before the 7-day limit.
- **Consider the `anon` key over `service_role`.** `service_role` bypasses RLS entirely,
  far more than a ping needs. Uncomment the RLS policy in
  [`keep-alive.sql`](sql/keep-alive.sql) to use `anon` instead.
- `targets.json` is gitignored. Anyone with write access to your repo can read the secret,
  as with every GitHub secret.

## Local run

```bash
export SUPABASE_KEEPALIVE_TARGETS="$(cat targets.json)"
bash scripts/keep-alive.sh
```

Requires `bash`, `curl`, `jq`.
