Keep your projects
from pausing.

In 4 easy steps.

Create the table.

Every project needs one tiny table for the ping to read. Copy this and run it in the SQL Editor of each Supabase project you want to keep alive.

keep-alive.sql 
create table if not exists "keep-alive" (
  id bigint generated by default as identity primary key,
  name text default '',
  random uuid default gen_random_uuid()
);
insert into "keep-alive" (name) values ('keep-alive');

Add your projects.

Open Settings → API in each project and copy its Project URL and service_role key. Test sends a live request to confirm the table is reachable.

Copy your config.

This is the value of the SUPABASE_KEEPALIVE_TARGETS secret. Save it as targets.json in the repo. That filename is gitignored.

targets.json

Save the secret.

Give the Action your config. From the repo root:

terminal 
gh secret set SUPABASE_KEEPALIVE_TARGETS < targets.json
  1. No GitHub CLI? Go to Settings → Secrets and variables → Actions
  2. New repository secret, named SUPABASE_KEEPALIVE_TARGETS, paste the config

That’s it.

Your projects get pinged every three days.

Import existing JSON

Paste a targets.json array to load it back into the form.

How it works.

01 The problem

Supabase pauses free-tier projects after 7 days without activity.

02 The fix

A GitHub Action reads one row from a small keep-alive table in each of your projects, every three days. That read counts as activity, so the timer never runs out. Each request uses a random filter value so nothing can answer it from cache.

03 What this page is

Only a config generator. It writes the JSON the Action reads and lets you test each project first. Closing the tab changes nothing. The Action does the work.

04 What you need

Your own fork of the repository, Actions enabled on it, the table created in each project, and the generated config saved as a repository secret.

05 Good to know

GitHub switches off scheduled workflows after 60 days with no commits. Any push resets it. An already-paused project has to be restored from the Supabase dashboard first; this prevents pausing, it can't undo it.
